# تفعيل ساعات المسجد عبر موقع بسيط — 2026-10-10

## الهدف والاتفاق

إضافة الساعات الجديدة دون إصدار APK لكل سيريال، مع استمرار عمل الساعات
المباعة بدون إنترنت. وافق المالك على التفعيل من شاشة الأجهزة، وعلى استعمال
`basitapps.com` بخدمة مستقلة عن WordPress. هذه مواصفة للتنفيذ؛ لم تنشر خدمة
ولم يعدل Android أو Firmware في مرحلة إعداد الوثيقة.

## حدود الإصدار الأول

- تفعيل سيريال واحد من الموقع وحفظ ترخيص دائم على الهاتف.
- الإبقاء على السيريالات القديمة المعتمدة خلال الانتقال.
- تسجيل السيريال والموديل من إدارة محمية على الموقع؛ لا تسجيل ذاتي للعملاء.
- لا حساب مطلوب للعميل ولا تنزيل لقائمة السيريالات كاملة.
- لا تعديل Firmware، ولا توقيع BIN، ولا مصادقة بمفتاح داخل الساعة في هذه الدفعة.
- لا انتهاء دوري للترخيص ولا شرط إنترنت في التشغيل اليومي.
- لا إصدار/نشر تطبيق أو رفع للخدمة ضمن إعداد التصميم.

## ما أثبتته قراءة Android

المشروع: `C:/Users/m_nag/Desktop/Android_Projects/MasjedClockWiFi`.

- `FirstActivity.copyDBFromAsset`: ينسخ SQLite المضمنة عند أول تشغيل.
- `DBManager.getModelCode/hasSerial`: يقرآن جدول Model من asset ثم القاعدة المحلية.
- `DeviceList.onDeviceSelected`: يختار شبكة الساعة أو يطلب فتح إعدادات Wi-Fi.
- `DeviceList.setDataFromBoard`: يفحص السيريال ثم رد checkUpdate.
- `DeviceList.setupInteractions`: الاتصال التلقائي يعتمد على isKnownDevice.
- `UpdateActivity.verifyTarget`: يستعمل موديل القاعدة أو الموديل الممرر من الاتصال.
- `WifiConnectionManager`: يستعمل bindProcessToNetwork لشبكة الساعة؛ طلب الموقع
  يحتاج اختيار شبكة إنترنت صراحة، مع DNS وsocket مربوطين بتلك الشبكة.
- `ClockKeyStore`: ملف موجود بلا callers؛ لا نعد وجوده حماية فعالة للقائمة.
- اختلاف موديل السيريال القديم عن الجهاز يسجل تحذيرًا حاليًا؛ ترخيص جديد
  موقّع يجب أن يرفض هذا الاختلاف قبل التحكم أو OTA. لا نطبق رفضًا عامًا على
  القديم دون مراجعة البيانات لأن الكود يسمح حاليًا بصفوف قديمة غير دقيقة.

## موضع الاستضافة

المسار المقترح `https://basitapps.com/clock-licenses/`، بمجلد تطبيق مستقل
ومعالجة مسارات مستقلة عن WordPress. الأفضل أن يكون حظر وصول الملفات الخاصة
على مستوى الاستضافة، وألا تمر طلبات API بمعالجة أو كاش WordPress.

التقنية المقترحة PHP مع MySQL وامتداد OpenSSL، بدون إطار عمل جديد. نوع
الاستضافة وإصدار PHP والامتدادات المتاحة لم يؤكدها المالك بعد؛ يلزم فحصها
قبل اعتماد حزمة تشغيل. لا يستنتج دعمها من الصفحة العامة للموقع.

## السيناريو

1. السبلاش يجهز التطبيق ويفتح شاشة الأجهزة دون انتظار الشبكة أو الموقع.
2. عند اختيار ساعة: يتحقق التطبيق من ترخيصها المحفوظ ثم اعتمادها القديم.
3. الترخيص المحلي صالح فقط بعد التحقق من توقيعه وتطابق سيرياله مع الاختيار.
4. المعتمدة محليًا تتابع الاتصال المعتاد بدون طلب موقع.
5. الجديدة تطلب ترخيصًا من الموقع قبل مطالبة المستخدم بالاتصال بشبكة الساعة.
6. إذا كان الهاتف متصلًا بها بالفعل، يستعمل طلب التفعيل شبكة إنترنت متاحة
   منفصلة. إذا تعذر ذلك، يحتفظ بالسيريال المختار ويعرض توجيهًا للاتصال
   بالإنترنت ثم إعادة المحاولة؛ لا يعد فشل الشبكة رفضًا للسيريال.
7. بعد نجاح التوقيع والحفظ: يكمل اختيار شبكة الساعة ثم checkUpdate.
8. يجب تطابق موديل الجهاز مع الترخيص الجديد قبل فتح التحكم أو رفع BIN.
9. الهاتف الجديد أو حذف بيانات التطبيق يستلزم تفعيل الساعات الجديدة مجددًا.

لا تعتبر موافقة Android على شبكة الساعة دليلًا على وجود إنترنت، ولا تغير
ربط شبكة الساعة عالميًا لإرسال طلب التفعيل بينما هناك اتصال أو OTA جارٍ.

## عقد الترخيص

`POST /clock-licenses/api/activate` عبر HTTPS، بجسم JSON يحتوي `serial` فقط.
السيرفر يحدد الموديل من سجلات المالك، لا من قيمة يرسلها العميل.

السيريال نص أرقام ASCII محدود الطول، وفق القيم الفعلية للمنتجات عند التنفيذ.
يجب الحفاظ على تمثيل السيريال القائم ومراجعة الأصفار البادئة قبل أي تطبيع؛
لا تحويل عددي صامت يغير هوية السجل. الموديل من قائمة الأنواع الحالية فقط.

نجاح HTTP 200 يرجع JSON بحقلين: `payload` و`signature`، كلاهما Base64.
payload بعد فك Base64 هو JSON UTF-8 يتضمن:

`version=1`, `purpose=basit-clock-license`, `serial`, `model`.

التوقيع ECDSA P-256 مع SHA-256 على بايتات payload الأصلية، بصيغة DER
المتوافقة بين OpenSSL وAndroid SHA256withECDSA. التطبيق يتحقق من البايتات
قبل استعمال الحقول؛ لا يعيد بناء JSON للتحقق. يرفض الحقول المكررة، إصدارًا
غير مدعوم، غرضًا مختلفًا، موديلًا غير مدعوم، أو سيريالًا مختلفًا.

المفتاح العام ضمن التطبيق؛ الخاص خارج مجلد الويب وخارج Git/APK وحزمة
التوزيع العامة. تجهيز المفتاح وتثبيت المفتاح العام يجب أن يسبقا بناء نسخة
تفعيل قابلة للاستخدام، بدون مفتاح تجريبي احتياطي يقبله إصدار الإنتاج.

- 404: غير مسجل.
- 403: غير متاح للتفعيل.
- 429: محاولات كثيرة؛ رسالة مؤقتة مع إعادة محاولة يدوية.
- أخطاء اتصال أو 5xx: تعذر التحقق، بدون حفظ نتيجة رفض دائمة.
- نجاح بتوقيع غير صحيح: لا اعتماد ولا استبدال لترخيص صحيح موجود.

حجم الاستجابة محدود ومهلة الطلب محدودة. لا إعادة محاولات لا نهائية ولا
تعطيل شاشة الأجهزة بعد رجوع المستخدم أو تدمير Activity. نتيجة أي طلب
متأخر لا تمنح صلاحية لسيريال اختاره المستخدم بعد بدء ذلك الطلب.

## التخزين والتكامل

يحفظ التطبيق payload والتوقيع معًا لكل سيريال بعد التحقق، ويفحصهما عند
استعمالهما. لا يعتمد على boolean مثل licensed=true. تشفير الكاش اختياري
ومستبعد من الإصدار الأول؛ السيريال معلن أصلًا في اسم شبكة الساعة.

نقطة اعتماد مشتركة تغطي اختيار الجهاز والاتصال التلقائي وقراءة الموديل
والتحقق قبل OTA. تبقى وظائف المدن والمواقع وقاعدة بياناتها كما هي.
السيريالات الجديدة تعتمد فقط بترخيص صحيح؛ لا تدخل إلى اعتماد القديم
لمجرد إضافة صف محلي غير موثوق. عند التنفيذ توثق حدود اعتماد القديم
الموجودة دون توسيعها، وتظل لقطة السيريالات القديمة المضمنة مرجع الانتقال.

## خدمة المالك

- سجل الساعات: serial فريد، model، وإتاحة إصدار تراخيص جديدة.
- إدارة منفصلة لتسجيل وتصحيح الساعات، محمية بتسجيل دخول وجلسات وCSRF.
- استيراد أولي للسيريالات القديمة فقط من جدول Model؛ لا نقل بيانات المواقع
  أو ملاحظات العملاء إلى endpoint العام. الصفوف model=0 أو المختلف عليها
  تحتاج مراجعة قبل إصدار ترخيص جديد لها.
- لا endpoint عام لتعداد كل الساعات أو إنشاء سيريال.
- HTTPS، استعلامات parameterized، حدود محاولات، ونسخ احتياطية للقاعدة والمفتاح.
- أداة التصنيع التلقائي متابعة لاحقة؛ لا اعتماد مجهول لمجرد وجود Firmware.

## التحقق المطلوب قبل التسليم

- متجه توقيع واحد من PHP ينجح في Android؛ تغيير السيريال أو الموديل أو
  التوقيع يفشل؛ إصدار/غرض مختلف أو payload مكرر الحقول يفشل.
- استجابة السيرفر لا تصدر ترخيصًا لسيريال غير مسجل أو موديل غير صالح.
- ساعة قديمة تعمل offline؛ ساعة جديدة تتفعل مرة ثم تعمل بعد restart offline.
- فقد الإنترنت أو السيرفر لا يعطل ترخيصًا صحيحًا موجودًا.
- اختيار ساعة أخرى أثناء الطلب لا يمنحها نتيجة الطلب السابق.
- الاتصال التلقائي وOTA يستعملان نفس اعتماد السيريال والموديل.
- هاتف متصل بشبكة الساعة مع بيانات هاتف، وهاتف بلا بيانات: اختبار فعلي
  لفصل الشبكات ورسالة إعادة المحاولة، مع العربية والإنجليزية.
- بناء Android وفحوص ملائمة؛ تجربة نشر في مسار تجريبي قبل الموقع الفعلي.

## حدود الحماية والتشغيل

هذا التصميم يثبت اعتماد السيريال في التطبيق الرسمي، ولا يثبت أصالة العتاد.
يمكن لنسخة Firmware معدلة انتحال سيريال معتمد، أو APK معدل تجاوز الفحص.
منع إصدارات تراخيص جديدة لا يبطل ترخيصًا دائمًا محفوظًا على هاتف offline.
توقف الاستضافة يعطل التفعيل الجديد فقط؛ يلزم حفظ المفتاح الخاص لاستمرار
إصدار تراخيص يقبلها التطبيق المنشور.
